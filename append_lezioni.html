Modulo finale 1 — Framework di decisione

Dal risultato NGS alla decisione clinica

Il framework proposto nelle lezioni originali separa cinque passaggi:

  1. Qualità e contesto del dato
  2. Tiering AMP/ASCO/CAP
  3. Actionability ESCAT
  4. Trade-off clinici
  5. Documentazione

1. Qualità e contesto del dato

Prima di classificare una variante chiediti:

  • la copertura è adeguata?
  • la purezza tumorale è sufficiente?
  • il dato è coerente con l’istologia?
  • il test è tumor-only o matched?
  • il risultato è tecnicamente interpretabile?

Regola

Prima validità analitica, poi interpretazione

2. Tiering AMP/ASCO/CAP

Tier I–IV

Il framework della lezione applica il tiering a:

  • SNV / indel
  • amplificazioni
  • fusioni

significato clinico

da

3. Actionability — ESCAT

Domanda

Quanto è forte l’evidenza che collega:

alterazione → farmaco → tumore → setting?

La lezione utilizza ESCAT come livello di actionability clinica.

Punto chiave

Variant pathogenicity ≠ actionability

4. Trade-off e documentazione

La decisione finale non è solo genomica.

Integra:

  • beneficio atteso
  • tossicità
  • logistica
  • preferenze del paziente
  • alternative
  • trial clinici
  • follow-up

Aleatoric vs epistemic uncertainty

Aleatoric

Incertezza intrinseca al dato.

Epistemic

Incertezza dovuta a:

  • limiti del modello
  • limiti del dato
  • tumor-only
  • conoscenza incompleta

Modulo finale 2 — RNAfusion

Una pipeline riproducibile per fusioni RNA-seq

La lezione descrive RNAfusion come pipeline nf-core costruita con:

  • Nextflow
  • Docker / Singularity
  • workflow standardizzato
  • supporto HPC / cloud
  • report HTML
  • controlli nf-core

RNAfusion — perché interessa il laboratorio clinico?

Riproducibilità

Stesso workflow
→ stesso ambiente software
→ maggiore tracciabilità

Portabilità

Laptop / server / HPC / cloud

Standardizzazione

Riduce la variabilità operativa tra analisi.

RNAfusion — esempio di esecuzione

nextflow run nf-core/rnafusion -profile test,docker

Domanda per la masterclass

Una pipeline riproducibile rende automaticamente clinicamente valido il risultato?

No.

La riproducibilità del workflow non sostituisce validazione analitica, QC e interpretazione.

Modulo finale 3 — SplitFusion

Dallo split-read al breakpoint

La lezione descrive SplitFusion come metodo che sfrutta:

chimeric split-read alignments di BWA-MEM

Applicabile a:

  • RNA-seq
  • Anchored Multiplex PCR

SplitFusion — pipeline analitica

  1. reference alignment e deduplication
  2. CIGAR transformation
  3. candidate breakpoint calling
  4. initial breakpoint filtering
  5. gene annotation
  6. frame-ness
  7. exon-boundary analysis
  8. further filtering
  9. reporting e visualization

SplitFusion — evidenza da auditare

Per una fusione clinicamente interpretabile valuta:

  • split reads
  • breakpoint consistency
  • unique fragment support
  • exon boundaries
  • frame-ness
  • mapping ambiguity
  • eventuali artefatti ricorrenti

Domanda

Fusion AI prompt — strutturato

ANALYTICAL EVIDENCE
- split-read count
- spanning-read count
- breakpoint
- MAPQ
- strand orientation
- in-frame / out-of-frame
- transcript / exon context

CLINICAL CONTEXT
- tumor type
- AMP/ASCO/CAP tier
- ESCAT level, if established

Return:
1. observed evidence
2. biological interpretation
3. evidence requiring external verification
4. unsupported conclusions

Le tre indicazioni finali

1 — Non saltare il livello analitico

Detection ≠ interpretation

FASTQ / BAM / IGV / QC vengono prima del tiering.

Le tre indicazioni finali

2 — Non confondere standardizzazione e validità clinica

Reproducible pipeline ≠ clinically validated result

RNAfusion / SplitFusion possono strutturare l’analisi, ma QC e validazione restano necessari.

Le tre indicazioni finali

3 — Non lasciare che l’AI fonda livelli diversi

Analytical validity

↓ # Biological meaning ↓ # Clinical actionability ↓ # Clinical decision

Devono rimanere esplicitamente separati.

Chiusura della masterclass

Evidence first. Context second. AI third.

Human verification always.
